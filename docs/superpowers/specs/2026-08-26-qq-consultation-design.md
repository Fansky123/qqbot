# QQ 咨询模式设计

## 目标

让授权 QQ 群成员可以通过 @范范获得 Codex 的咨询回复，同时保留现有任务创建、确认和执行流程。咨询绝不创建任务、绝不进入 scheduler，也不具备写代码、Git、合并或 RC 部署权限。

## 消息语法

| 场景 | 格式 | 行为 |
| --- | --- | --- |
| 通用咨询 | `@范范 问题内容` | 在独立、空白的咨询工作目录中回答，不读取项目代码。 |
| 项目咨询 | `@范范 问 [项目别名] 问题内容` | 仅以对应项目仓库为只读上下文回答。 |
| 创建任务 | `@范范 [项目别名] 任务内容` | 保持当前规划、确认和执行流程。 |
| 任务操作 | `确认 #T-...` 等现有命令 | 保持当前行为，@ 为可选。 |

方括号前没有 `问` 的消息始终是任务创建，不用模型猜测意图。`问` 后缺少问题、项目别名未知、没有 @机器人，均返回有界错误，不调用 Codex。

## 处理与权限

OneBot 已经把真正 @范范 的消息标记为 `Mentioned`。消息进入应用后，继续先过滤群号与用户白名单；只有授权员工和管理员可以咨询或创建任务。

命令解析新增两种咨询命令：通用咨询和项目咨询。任务命令仍由 `tasksvc.Service` 单独处理；咨询由独立服务处理，并只依赖授权、咨询运行器、持久化去重记录、日志脱敏器和 QQ 通知器。它不接收 scheduler、worktree manager 或 ops client，防止职责边界被绕过。

每个咨询按一条 QQ 消息独立处理，不继承前一条咨询的会话或群聊上下文。这样不会把不同员工的对话串在一起，也不会在本地保留可继续的 Codex 会话。

## Codex 安全边界

咨询运行器复用已验证的凭据清洗、超时、进程组取消、输出限额与日志脱敏能力，但使用一个单独的只读调用方式：

- 通用咨询在新配置的私有咨询目录中运行；该目录不可与数据库、日志、worktree 或项目仓库重叠。
- 项目咨询以配置项目的 `repo_path` 为工作目录。
- 所有咨询调用都使用 Codex CLI 的 `read-only` sandbox 和临时会话模式，不创建可恢复 session。
- 咨询提示词明确要求只回答问题，禁止写文件、创建任务、调用 Git/部署命令或泄露凭据。
- 不为咨询开启 Web 搜索；模型只有本地只读上下文。

咨询超时使用单独的配置值，并采用保守默认值。回复沿用当前 OneBot 的 Unicode 安全分段、最大长度与凭据脱敏规则。调用失败、超时或输出无效时，只回传通用失败说明；详细错误保留在本地受限日志中。

## 幂等与审计

新增咨询记录，键为 `group_id + message_id`。首次处理时保存咨询类型、项目（如有）、发起人、时间和已脱敏的有界回复；重复 OneBot 事件直接重放该回复，不再次调用 Codex。

咨询记录不属于任务，不生成 `T-` 编号，不改变任务状态，也不唤醒 scheduler。咨询输入和输出仍按现有本地日志权限、脱敏与保留策略处理；不会存储可继续的聊天会话。

## 错误与并发

现有 `message_workers` 限制继续覆盖咨询调用。授权失败、无效命令和不支持的消息不产生 Codex 调用或持久化副作用。持久化成功但 QQ 通知失败时，重放同一消息只发送已保存回复，不重复咨询。

## 测试

- 命令解析覆盖通用咨询、带项目别名的咨询、缺少 @、空问题及与任务语法的无歧义分流。
- 咨询服务覆盖群/用户授权、通用与项目工作目录选择、只读运行器调用、脱敏、回复限额、重复消息重放和通知失败重试。
- Codex 运行器覆盖咨询调用参数：只读 sandbox、临时会话、通用咨询的非 Git 工作目录，以及不传递敏感环境变量给模型工具。
- 应用集成测试覆盖 OneBot `@范范` 咨询回复、任务创建仍需方括号项目别名，以及咨询不创建任务、不调用 scheduler 或 ops。

## 非目标

- 不支持连续多轮聊天、引用消息续聊或跨群记忆。
- 不支持非 @消息触发咨询。
- 不提供浏览网页、Shell 命令、文件写入、Git 提交/推送、合并或部署能力。
